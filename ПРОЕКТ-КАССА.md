## 1. ЧТО ЭТО
Система для розничного магазина из **трёх частей**:

| Часть | Папка | Что делает | Технологии |
|---|---|---|---|
| **Касса (ноут)** | `new kassa\kassa` | Продажи, склад, смены, расходы, печать чеков/этикеток | Python + PyQt6, SQLite |
| **Сервер** | `new kassa\kassa-backend` | Прослойка между устройствами и базой | Python + FastAPI |
| **Приложение-админ (телефон)** | `new kassa\kassa-admin` | Выручка, смены, товары, отчёты, админы | React Native (Expo) |
| **База** | MongoDB Atlas (облако) | Хранит всё | MongoDB |

Схема:
```
Ноут-касса ─┐
            ├─→  Сервер (FastAPI, порт 8000)  →  MongoDB Atlas
Телефон ────┘
```

## 2. КЛЮЧЕВЫЕ ФАКТЫ (запомнить)
- **PIN для входа в приложение (демо-админ): `111111`** (магазин «Магазин Центр»).
- **Сервер:** `http://192.168.1.16:8000` (IP меняется при смене сети; в приложении правится в «Настройки»; в коде — `kassa-admin/src/config.ts`).

- ⚠️ **АРХИТЕКТУРА:** ноут разработки — **ARM64**. Кассовый ноут — **Intel (x64)**.
  ARM-программа на Intel НЕ запускается. Собранный здесь `Kassa.exe` — под ARM,
  для Intel нужна **x64-сборка** (см. раздел «Осталось»).

## 3. КАК РАБОТАЕТ ДОСТУП (PIN и магазины)
1. Ноут-касса создаёт магазин на сервере → получает секретный `store_key`.
2. В **Настройках кассы** кнопка **«➕ Добавить админа»** → сервер генерирует
   **PIN** нового админа.
3. Владелец диктует PIN человеку. Тот вводит PIN в приложении на телефоне →
   входит как админ этого магазина, видит данные + список других админов.
4. У каждого админа — свой PIN (только у него).

## 4. ЧТО УЖЕ СДЕЛАНО ✅

### Касса (десктоп)
- Ускорение базы (индексы) — на объёме 5 лет всё быстро.
- Архив чеков: один .txt-файл на **2.5 недели** (а не на каждый чек).
- **Раздел «Расходы»**: 2 поля (на что / сколько взяли из кассы) + кнопка «Добавить».
  Наличные в кассе = сдача + продажи наличными − расходы.
- Фикс печати чеков (был баг `winspool` → исправлен, `kassa/printer.py`).
- Кнопка «Добавить админа» (Настройки → Сервер).
- Иконка приложения — фото с деньгами (`kassa/icon.ico`).
- Инсталлятор Inno Setup (`installer.iss`), ставится без прав админа в
  `%LOCALAPPDATA%\Programs\Kassa`, данные — в `%LOCALAPPDATA%\Kassa`.
- **Автотест 25/25 функций** прошёл (продажа, склад, смены, расходы, печать,
  сервер, офлайн-очередь и т.д.).

### Сервер (FastAPI)
- Вход по PIN, магазины, товары (+сумма склада), смены с итогами, отчёты
  (выручка за период, по дням), «Добавить админа», список админов.
- Приём **Z-отчётов** с кассы: `POST /ingest/report` (защита ключом магазина).
- Индексы, health-check, Swagger. Работает на **реальной MongoDB** — проверено.

### Приложение (Expo / React Native)
- Экран входа по **PIN** (крупные цифры).
- Вкладки: Дашборд (выручка + график по дням), Товары (+сумма склада),
  Смены (открытые/закрытые с итогами), **Админы** (список), Настройки (адрес сервера).
- Переключатель магазинов. TypeScript чист, бандл собирается.
- Данные тянутся с сервера — проверено реальным входом по PIN 111111.

### Синхронизация касса → сервер (офлайн-очередь)
- На сервер уходит **только Z-отчёт при закрытии смены**: сколько в кассе,
  наличными, в банке, расходы, продажи, часы. Продажи по одной НЕ шлём.
- **Нет интернета** → смена НЕ закрывается, отчёт копится в очереди (`sync_queue`).
- Таймер **каждые 30 сек** проверяет связь; появилась → отчёт уходит, смена
  закрывается, уведомление «успешное подключение». Проверено тестом.

## 5. ЧТО ОСТАЛОСЬ ⏳

1. **Пересобрать кассу под x64 (для Intel-ноута).** На ARM-ноуте exe собран под ARM.
   x64-Python уже стоит (`C:\PythonX64`), x64-сборка была в `kassa/dist-x64`.
   На Intel проще собрать нативно: x64-Python + `pip install pyqt6 pyinstaller` → `build.bat`.
2. **APK для телефона.** Собирался локально (JDK17 + Android SDK), настроен на
   `arm64-v8a`. Был на этапе нативной компиляции — добить: в `kassa-admin/android`
   → `gradlew assembleDebug`. Либо через EAS Build (нужен аккаунт Expo).
3. **Драйвер принтера этикеток XP-350B** — поставить `Xprinter_2020.1.exe` на
   **Intel-ноуте** (под ARM драйвера нет вообще). Тогда печать этикеток из кассы заработает.
4. **C4 — экран Z-отчётов в приложении** (эндпоинт `/reports/shifts` на сервере готов).
5. **Хостинг сервера** — вынести в интернет (Render/Railway/VPS), чтобы телефон
   работал откуда угодно, а не только в одной wifi.
6. **Безопасность:** сменить пароль MongoDB в Atlas, убрать доступ `0.0.0.0/0`,
   почистить демо-данные, когда пойдут реальные.

## 6. ПРИНТЕРЫ
- **POS58** (чеки, язык ESC/POS) — работает через встроенный драйвер Windows (IPP).
  На ARM-ноуте печатает. Формат чека: шапка магазина, товары, итог, штрихкод чека.
- **XP-350B** (этикетки/ценники, язык **TSPL**):
  - Драйвер только под x86/**x64**, **ARM-версии НЕТ** → на ARM-ноуте не работает никак.
  - На **Intel-ноуте заработает** (поставить драйвер Xprinter).
  - **Калибровка** (зазор между этикетками): на самом принтере — выключить →
    зажать кнопку **FEED** → включить, держать пока не протянет 1-2 этикетки.
  - Формат ценника (кнопка «Этикетка» в Складе): магазин, товар, штрихкод, цена.

## 7. КАК ПРОДОЛЖИТЬ НА ДРУГОМ (Intel) НОУТЕ
1. Скопировать папку **`new kassa`** (можно без `node_modules`, `dist`, `build`,
   `.gradle` — они восстанавливаются; но с `.env`!).
2. Поставить: x64 **Python 3.13** (python.org), **Node.js**, при желании Android-тулчейн.
3. Открыть папку в **Claude Code**, дать файл `new kassa\ПЕРЕДАЧА.md` (или этот) →
   продолжить.
4. Первые шаги: собрать `Kassa.exe` нативно под x64, поставить драйвер XP-350B,
   проверить печать чека (POS58) и этикетки (XP-350B), добить APK.

Вариант «в web»: залить `new kassa` на **GitHub**, открывать из **claude.ai/code**
с любого устройства (нужен вход в GitHub; `.env` с паролем НЕ заливать).
